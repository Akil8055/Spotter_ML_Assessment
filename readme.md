# Freight Rate Prediction

Machine-learning solution for the freight-rate prediction assessment. The work was carried out in a Jupyter notebook, using exploratory analysis, data cleaning, feature engineering, chronological validation, model comparison, and a final CatBoost model.

## Repository contents

```text
freight-rate-prediction/
├── README.md
├── requirements.txt
├── validation_predictions.csv
├── score.py                         # assessment-provided scorer utility
├── notebooks/
│   └── eda.ipynb                    # EDA, preprocessing, experiments, and model workflow
├── scorer_results/
│   └── candidate_december.png       # chart generated by score.py
└── report/
    └── freight_rate_prediction_report.pdf
```

The `data/` folder is expected locally but is not included in this repository because it contains assessment-provided input data. The empty `src/` files are intentionally not listed: the implemented modelling workflow is in `notebooks/eda.ipynb`.

## Task and data

The goal is to predict the freight-load target `posted_rate`.

- Labeled development data: 48,000 rows, dated 1 January to 31 October 2025.
- Unlabeled prediction data: 12,000 rows, each identified by `load_id`.
- December chart inputs: 31 daily records for a fixed shipment configuration.

The final validation submission is `validation_predictions.csv` and must contain exactly two columns, in this order:

```csv
load_id,predicted_rate
```

The completed December scorer input has exactly these seven columns:

```text
pickup,delivery,distance,equipment,weight,date,predicted_rate
```

## Run the workflow

1. Place the assessment input files in a local `data/` directory. Use the filenames/paths expected by the notebook; adjust the notebook's read paths if the provided files use hyphens rather than underscores.
2. Open `notebooks/eda.ipynb` in VS Code or Jupyter and run the cells in order. The notebook contains the exploratory analysis, preprocessing, feature engineering, chronological split, model experiments, final model fit, and prediction generation.
3. Confirm that `validation_predictions.csv` is generated with 12,000 rows and exactly `load_id,predicted_rate`.
4. Fill the December input template with the `predicted_rate` values generated by the final model, preserving the exact seven-column schema.
5. From the repository root, run the assessment-provided scorer:

```bash
python score.py --predictions validation_predictions.csv --december-predictions data/december_chart_inputs.csv
```

A successful run validates the prediction-file structure and values and creates `scorer_results/candidate_december.png`. The scorer does not calculate hidden-label prediction accuracy; the assessment platform calculates final metrics after submission.

## Data preparation and feature engineering

The notebook performs the following operations:

- Parses the date and derives `year`, `month`, `day`, `day_of_week`, `day_of_year`, and `is_weekend`.
- Builds a `route` field from pickup and delivery locations.
- Records missing-weight and negative-weight indicators.
- Treats negative weights as missing rather than converting them to absolute values.
- Adds `distance_squared` and `distance_per_weight`.
- Excludes `price_per_distance` from model inputs because it uses the target `posted_rate` and would cause target leakage.

The final common-feature model uses 16 inputs available from the six source fields in both prediction settings: `pickup`, `delivery`, `distance`, `equipment`, `weight`, and `date` (plus derived features). Coordinates, `market_index`, and `quote_signal` are not used by the final common-feature model because they are not present in the December template.

## Validation methodology

A chronological holdout was used to approximate future prediction:

- Training: dates before 1 September 2025 — 38,477 rows.
- Validation: 1 September through 31 October 2025 — 9,523 rows.

The features and target were rebuilt after sorting by date, and their indices were checked for alignment. After model selection, the final common-feature CatBoost model was refitted on all 48,000 labeled records before generating the final predictions.

## Model comparison

The following results were recorded on the chronological holdout. MAE and RMSE are in the same units as `posted_rate`; lower is better. Higher R² is better.

| Model | MAE | RMSE | R² |
|---|---:|---:|---:|
| Mean baseline | 1,178.8033 | 1,526.2263 | -0.0002 |
| Original CatBoost | 113.9046 | 633.6758 | 0.8276 |
| Log-target CatBoost | 113.5560 | 635.4788 | 0.8266 |
| XGBoost | 163.9005 | 663.6766 | 0.8109 |
| Engineered CatBoost (full features) | 109.2419 | 633.0680 | 0.8279 |
| Common-feature CatBoost (selected) | 122.5832 | 633.8997 | 0.8275 |
| December-compatible CatBoost experiment | 122.9862 | 633.4106 | 0.8277 |

The engineered full-feature CatBoost had the lowest MAE among the recorded experiments. The common-feature CatBoost was selected as the final operational model because its input features can be constructed for both the 12,000-row validation file and the December template. Its MAE was approximately 12.2% higher than the full-feature engineered model, while RMSE and R² remained similar.

### Final model configuration

- Model: CatBoost Regressor
- Iterations: 175
- Learning rate: 0.05
- Depth: 8
- Loss: RMSE
- Random seed: 42
- Training rows for final fit: 48,000
- Input features: 16 common features

## Selected exploratory findings

- `posted_rate`: mean 2,373.98; median 2,030.76; standard deviation 1,486.49; minimum 57.22; maximum 25,533.00.
- `distance`: mean 1,135.86; median 953.30; standard deviation 728.56; minimum 70; maximum 3,439.8.
- The training data contained 300 missing weights and 292 negative weights. Negative values were treated as invalid and set to missing.
- The training data contained 374 missing `market_index` values; `market_index` was not used in the final common-feature model.
- Equipment counts: Dry Van 27,202; Reefer 12,045; Flatbed 8,753.
- In the engineered full-feature CatBoost experiment, `distance_squared` and `distance` had feature-importance scores of 49.68 and 31.86 respectively. Feature importance is model-specific and does not establish causation.
- Prediction errors were substantially larger in the rare validation rate bands above 7,000. These cases were a small fraction of the holdout and contributed to the gap between MAE and RMSE.

## Notes and limitations

- The local scorer's successful run confirms expected file structure, row counts, identifiers, numeric positive predictions, fixed December inputs, and chart creation. It does not confirm hidden-label accuracy.
- The final model is intended to provide one consistent feature interface for the validation and December prediction tasks.
- The December chart is a model prediction for one fixed route/configuration, not observed market pricing and not a general forecast for all freight lanes.
